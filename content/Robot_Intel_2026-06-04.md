# 具身智能情报前沿｜坏行为数据成为奖励模型新缺口

**作者：具身视界** · 2026.06.04

> 今天具身智能数据最值得看的变化，是研究者开始把目光从“更多成功示范”转向“更完整的行为分布”。真实部署中的机器人不会只遇到标准成功轨迹，还会出现碰撞、误抓、投机取巧、危险接触、长程探索失败和跨硬件错位；这些负样本、风险样本和对齐样本，正在成为训练可靠奖励模型与安全策略的关键数据资产。

---

## 💥 今日重磅

### [ICML Spotlight观点文：具身奖励模型不能只看成功示范，必须补齐“坏机器人数据”](https://arxiv.org/abs/2606.01036)

**摘要：** 5 月 31 日提交的 `Position: Good Embodied Reward Models Need Bad Behavior Data` 被 ICML 2026 position track 接收为 spotlight。论文提出一个很直接但容易被忽视的判断：要训练可靠的具身奖励模型，社区不能只收集成功、漂亮、干净的机器人行为，还必须系统整理失败、次优、错误甚至危险行为数据。作者分析三类前沿具身奖励模型后发现，现有模型会系统性高估人类评估者会惩罚的行为，包括不安全交互、执行质量差、走捷径和表面完成任务。论文将原因归结为负样本数据缺口：坏行为采集成本高，且常在公开机器人数据集中被过滤、隐藏或直接丢弃。更重要的是，作者指出即使只加入适量真实坏行为数据，也能提升奖励模型与人类偏好的对齐，减少高成本误判正例。

- **来源：** arXiv / ICML 2026 position track
- **核心价值：** 这条进展说明，具身智能数据竞争正在从“谁有更多成功轨迹”走向“谁拥有更完整的行为分布”。对于人形机器人、协作机械臂和服务机器人来说，真正决定部署安全性的，往往不是模型见过多少成功样本，而是它是否见过足够多会出错、会危险、会被人类否定的行为。

## 📰 行业新闻

### 1. [EMBGuard用15.1K动作条件风险数据训练安全护栏，覆盖7类真实物理风险](https://arxiv.org/abs/2605.30924)

**摘要：** `EMBGuard: Constructing Hazard-Aware Guardrails for Safe Planning in Embodied Agents` 面向 MLLM 具身智能体的物理安全问题。系统独立于主策略，对“视觉观察 + 候选动作”进行风险判断，并给出自然语言解释。论文发布 `EMBHazard` 训练集，包含 `15.1K` 个 action-conditioned pairs；同时发布 `EMBGuardTest`，包含 `329` 个人工整理真实场景，覆盖 `7` 类物理风险。小型 `2B / 4B` 模型即可达到接近闭源 MLLM 的风险识别能力，并显著降低误报率。

- **来源：** arXiv / ICML 2026 / GitHub
- **核心价值：** 这是今天的数据相关报道。安全数据不应只是事故复盘材料，而应进入具身规划链路，成为每个候选动作执行前的实时风险过滤器。

### 2. [Dexterity-BEV开放跨机器人数据对齐管线，把3D世界和动作统一到BEV坐标](https://arxiv.org/abs/2606.02274)

**摘要：** `Dexterity-BEV` 关注机器人操作数据的空间与时间错位。论文提出 aligned vertex map 和 vertex spectrum，将 2D RGB 输入提升为像素级 3D 表示，并把相机视角、机器人动作和轨迹都对齐到共享坐标，再构造 canonical BEV alignment frame。项目还提供跨机器人、跨人类操作者、跨数据集的时间对齐方案，并开放预训练 checkpoint、源码和数据处理管线。

- **来源：** arXiv / Dexterity-BEV 项目页
- **核心价值：** 当数据来自不同机械臂、不同相机和不同采集流程时，更多数据不一定更好。统一坐标和时间基准，才是多源机器人数据真正可复用的前提。

### 3. [MineExplorer用多智能体合成任务图和评估器，构造开放世界长程探索数据](https://arxiv.org/abs/2605.30931)

**摘要：** `MineExplorer` 用 Minecraft 评估 MLLM 智能体开放世界探索能力。它先过滤过度依赖游戏专属知识的原子任务，再按 ReAct 风格能力组织 benchmark，并将原子任务组合为隐式多跳任务。为提升实例可靠性，团队使用多智能体合成工作流共同设计任务图、沙盒场景和规则里程碑评估器。人类评估显示，多智能体合成实例比单智能体基线更可靠；实验也表明，强模型在长轨迹隐藏前置条件下仍明显退化。

- **来源：** arXiv / GitHub
- **核心价值：** 开放世界具身评测不能只靠短任务。多智能体合成任务图和评估器，为长程探索数据的规模化生产提供了新方法。

## 📑 前沿论文

### 1. [GraspGen-X用20亿抓取样本训练跨本体6-DOF抓取，面向新夹爪零样本泛化](https://arxiv.org/abs/2606.00998)

**摘要：** `GraspGen-X: Cross-Embodiment 6-DOF Diffusion-based Grasping` 研究跨夹爪形态的 6-DOF 抓取生成。方法在扩散式抓取模型中加入夹爪表示条件，并提出 swept-volume heuristic 编码夹爪。训练侧，团队使用程序化夹爪和 `2 Billion` 抓取数据构建大规模训练集。仿真实验显示，该方法在零样本泛化到真实新夹爪和新物体时优于基线，也可作为新夹爪微调初始化。

- **作者团队：** Beining Han、Yu-Wei Chao、Erwin Coumans、Clemens Eppner、Balakumar Sundaralingam、Jia Deng、Stan Birchfield、Adithyavairavan Murali
- **来源：** arXiv
- **核心价值：** 机器人末端执行器变化会造成数据断裂。程序化夹爪和超大规模抓取样本表明，跨本体数据可以把硬件变化提前纳入训练分布。

### 2. [AnyMo依托OmniHuMo 5000小时运动数据，实现任意模态条件人体运动生成](https://arxiv.org/abs/2605.29488)

**摘要：** `AnyMo: Scaling Any-Modality Conditional Motion Generation with Masked Modeling` 面向多模态条件人体运动生成，发布 `OmniHuMo` 数据集：包含超过 `5,000` 小时运动、`3.2M` 条序列，并配有文本、语音、音乐和轨迹等精确对齐的多模态标注。AnyMo 使用 Residual FSQ 运动 tokenizer 和 masked modeling Transformer，在任意模态组合条件下生成高质量运动，并支持空间和风格属性控制。

- **作者团队：** Yiheng Li、Zhuo Li、Ruibing Hou、Yingjie Chen、Hong Chang、Hao Liu、Shiguang Shan
- **来源：** arXiv
- **核心价值：** 虽然这不是机器人本体数据集，但它对具身智能很有启发：人形机器人、虚拟人和远程协作都需要可控人体运动先验，大规模多模态运动数据会成为动作生成和人机交互的重要补充。

### 3. [TokTalk构建音频token到3D面部运动数据集，降低对话式具身交互的表情延迟](https://arxiv.org/abs/2605.31294)

**摘要：** `TokTalk: Expressive Real-time Facial Animation from Audio-LLM Tokens` 关注对话式具身智能中的实时表情生成。传统流程往往经历语音识别、文本生成、语音合成和音频驱动面部动画多个阶段，容易造成延迟和表情割裂。TokTalk 直接从流式 Audio-LLM tokens 输出 3D 面部动画，并构建 audio-token 到 3D facial motion 的新数据集，用 Chunk-based Conditional Flow Matching 训练。系统可在延迟与表情质量之间调参，并在感知研究中显示出更好的质量、表现力和控制性。

- **作者团队：** Qingcheng Zhao、Yifang Pan、Karan Singh
- **来源：** arXiv
- **核心价值：** 具身智能的数据不只包括操作轨迹，也包括面部、语音和交互时序。实时表情数据会影响社交机器人、数字人和远程具身代理的交互可信度。

## 💻 开源生态

### 1. [EMBGuard开源代码、数据和模型，动作风险评估可接入具身规划系统](https://github.com/dongwxxkchoi/EMBGuard)

**摘要：** EMBGuard GitHub 仓库公开代码、数据和模型，包含 `EMBHazard` 训练数据与 `EMBGuardTest` 测试集。它以视觉观察和候选动作为输入，输出风险判断与自然语言解释，可作为具身智能体规划前后的安全检查模块。

- **来源：** GitHub / arXiv
- **核心价值：** 安全数据集只有能接入实际规划链路，才会从论文指标变成部署工具。EMBGuard 的价值在于把风险识别做成了可调用模块。

### 2. [Dexterity-BEV项目页开放checkpoint、源码和数据处理管线，服务跨数据集操作学习](https://hnuzhy.github.io/projects/Dex-BEV)

**摘要：** Dexterity-BEV 项目页提供预训练权重、源码和数据处理流程，重点解决多相机、多机器人和多数据集下的空间-动作对齐。其 BEV 表示让视觉输入和机器人动作处于统一坐标，便于跨平台策略训练与评估。

- **来源：** Dexterity-BEV 项目页
- **核心价值：** 对机器人团队来说，数据处理管线本身就是基础设施。能否把历史轨迹规范化、对齐和复用，会直接影响模型训练效率。

## 🏢 数据与平台情报

### 1. [RoboDream继续提示：世界模型正在把旧轨迹变成可复用数据资产](https://arxiv.org/abs/2606.02577)

**摘要：** RoboDream 通过面向本体的组合式世界模型，将已有机器人运动轨迹迁移到新物体、新场景和新视角，还提出无道具遥操作流程：操作者先在空中完成动作，模型事后补全目标物体和场景。真实机器人实验显示，生成数据能够提升下游策略表现并减少真实数据需求。

- **来源：** arXiv / RoboDream 项目页
- **核心价值：** 机器人公司的历史轨迹库不应只是归档资产。通过世界模型重生和改写，旧数据可以持续产生新训练价值。

### 2. [坏行为数据观点推动数据治理变化：失败样本不应被默认过滤](https://arxiv.org/abs/2606.01036)

**摘要：** 坏行为数据论文呼吁社区公开失败、次优和危险行为数据，并建设合成坏数据生成引擎、去中心化物理评估系统和细粒度具身奖励模型评测基准。这一观点对数据治理提出新要求：采集平台不应只保留成功片段，也要记录失败类型、环境上下文、风险级别和人类偏好反馈。

- **来源：** arXiv / ICML 2026 position track
- **核心价值：** 失败数据的结构化治理，会决定奖励模型能否真正理解“不该做什么”。这也是机器人安全从规则工程走向数据工程的关键一步。

## 结尾总结

今天这期具身智能数据情报里，最清晰的趋势是：机器人数据正在从“成功示范库”变成“全行为分布库”。

坏行为数据论文把失败、次优和危险行为推到奖励模型训练的中心；EMBGuard 将动作条件风险做成可训练、可测试、可解释的数据集；Dexterity-BEV 解决多源轨迹的空间与时间对齐；GraspGen-X 用 `2 Billion` 抓取样本覆盖夹爪形态变化；MineExplorer、AnyMo 和 TokTalk 则分别从长程探索、人体运动和交互表情扩展具身数据边界。下一阶段的数据平台，不能只问“成功率有多高”，还要回答：**失败如何记录、风险如何标注、跨本体如何对齐、交互如何同步。**
