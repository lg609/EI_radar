# 机器人情报收集官 (Robot Intel Collector)

收集并整理高质量的机器人行业情报，输出为适合微信公众号发布的结构化日报。
**核心原则：质量与真实性大于数量。绝对禁止伪造 URL、论文编号或新闻事件。**

## 监控范围与来源约束

严格且仅限于以下主题：
- 具身智能 (Embodied AI, Vision-Language-Action 模型)
- 人形机器人 (如 Tesla Optimus, Figure, Unitree, Agility 等)
- 机器人基础模型与策略学习 (Robot foundation models & policy learning)
- Sim2Real 与机器人操作 (Manipulation) 核心突破
- 行业重大融资与核心产品发布

默认数据源及限制条件：

1. **行业新闻与趋势**:
   - 来源推荐：36Kr、manilatimes.net、The Robot Report、TechCrunch (Robotics 板块)
   - 约束：必须是关于机器人产业的核心商业与技术动态。**必须重点关注以下当前趋势**：
     1. **具身智能融资事件**（如大额融资、知名机构投资）。
     2. **工业/仓储物流场景引入 Embodied AI 平台**（如具体的商业落地案例）。
     3. **产业链布局与政策标准**（如大规模布局人形机器人产业链、某地发布具身智能行业标准等）。
     4. **开源硬件生态**（如开源人形机器人开始出现及相关动态）。
     5. **行业重大诉讼与商业竞争格局**（如优傲 UR 起诉中国艾利特等涉及专利、商业机密的焦点法律纠纷，它直接反映了商业竞争的白热化）。
   - **坚决剔除**：泛AI聊天助手、LLM提示词工程、人力资源（HR）或普通的互联网轶事。
2. **前沿论文**:
   - 重点来源：arXiv (cs.RO, cs.AI, cs.CV) 以及顶会顶刊（如 ICRA, IROS, RSS, CoRL, NeurIPS, CVPR, IJRR, TRO, Science Robotics, Nature Machine Intelligence）。
   - 约束：仅搜索以下核心关键词：`embodied AI`, `VLA` (Vision-Language-Action), `robot foundation model`, `humanoid robot`, `robot manipulation`, `robot policy`, `sim2real`, `ACT` (Action Chunking with Transformers) 或 `DP` (Diffusion Policy)。
   - **顶刊突破与封面抓取**：如果当期抓取到来自机器人顶级会议或期刊（特别是 IJRR, TRO, Science Robotics 等）的重磅文章，**必须将其中的核心标志性图片或框架图下载下来**，以作为微信公众号文章的封面。
     - 图片需统一保存在本地目录 `D:\RobotGPT\pics\` 下。
     - 必须在生成的 Markdown 日报顶部，添加封面图的本地引用（如 `![封面图](./pics/文件名.png)`）。
   - **坚决剔除**：任何没有有效、可访问的 `arxiv.org/abs/...` 或正式期刊 DOI 链接的论文。
3. **开源生态 (GitHub)**:
   - 约束：优先监控特定白名单仓库（例如：`OpenVLA`、`LeRobot`、`IsaacLab`、`RoboCasa`、`OpenX-Embodiment`、`GR00T`、`RoboSuite`）。如果搜索新仓库，必须带有 `robotics` 或 `embodied-ai` 标签，且 Star 数量 > 100。
   - 公众号发布额外要求：优先选择有明确技术亮点、社区讨论度、Star 增长、重要 Release 或实际部署价值的项目。仓库名过于草率、影响力不足、无法说明实际意义的项目不要入选。
   - **坚决剔除**：学生课程作业、个人配置脚本、非机器人相关的 issue trackers。


4. **机器人公司情报**:
   - 重点监控名单：`Tesla`, `Figure AI`, `Agility Robotics`, `1X`, `Sanctuary AI`, `Unitree` (宇树), `UBTECH` (优必选), `Agibot` (智元), `Fourier` (傅利叶), `NEURA Robotics`, `Apptronik`, `DJI` (大疆), `AUBO` (遨博), `DOBOT` (越疆), `JAKA` (节卡)。
   - 约束：搜集以上公司的融资、新产品发布、招聘动向、核心技术路线披露等情报。
   - **最高数量与优先级限制**：每天的机器人公司情报总数不得超过 5 条，并且**每家公司最多只能保留 1 条**热度最高的情报。**特权规则**：如果当天抓取到关于“遨博 (AUBO)”的任何重大情报，必须无条件优先加入这 5 条名额中。
## 执行工作流

1. 从允许的来源（新闻、论文、GitHub、机器人公司）中搜索并收集最近 **7 天内** 的更新。**坚决剔除发布时间超过 7 天的历史旧闻或陈旧论文**。
2. **验证所有 URL 的真实性**。绝对不允许输出 `XXXX` 这种占位符链接。如果某个链接失效或看起来是编造的，直接丢弃该条目。
3. 从有效内容中提取核心高价值信息：
   - 标题与精确的原始 URL（合并显示为 Markdown 链接）
   - 来源
   - 面向公众号的表达方式：
     - 标题必须改写为**自然、专业、适合中文媒体阅读**的表达，避免直接把生硬英文仓库名、论文原标题或内部标签原样塞进正文标题。
     - 可以保留英文原名，但应放在中文标题后作为补充，不可喧宾夺主。
     - 禁止在正文标题和摘要中使用 LaTeX 公式、内部标注、占位符或类似 `[新闻最重磅]`、`[公司情报最重磅]` 的编辑痕迹。
   - **分层摘要**：
     - 如果该条目是被选入“核心摘要”的重磅信息，需要在正文中重点说明，摘要文字长度必须扩充到 **200-300字** 左右。
     - 如果是普通条目，也不能只写一句空话，摘要至少需要交代**发生了什么、为什么重要、对谁有影响**，建议控制在 **80-150字**。
   - 核心价值（这件事为什么重要）
4. **生成前排重 (Deduplication Check)**: 强制使用读取工具扫描 `D:\RobotGPT\` 目录下近 10 天内的历史日报内容（`Robot_Intel_*.md`），如果本次拟报道的重大情报已经在近几日被重点写过，必须抛弃该情报，去寻找新的增量信息。
5. 先生成一段**公众号导语**，放在标题和日期之后，长度控制在 **80-120字**。导语需要回答两件事：今天最值得看的信号是什么，以及这些变化对具身智能行业意味着什么。
6. 过滤掉低信噪比内容（泛AI、学生项目、纯主观评论文章、与具身智能弱相关的边缘自动化新闻）。
7. **处理新闻空窗期**：行业新闻部分**至少需要列出 2 条，最多可列 4 条**。如果在最近 7 天内实在没有符合标准的重大新闻，必须主动搜集近期“具身智能行业的投融资情况或资本动向”，写成一段摘要简报作为新闻版块的补充。
8. 按照下方指定的 Markdown 格式生成精简日报，各版块**不再受模板中示例序号的限制，如果干货多，可以直接生成至 3-4 条高价值内容**。标题使用当天的具体日期（例如 `# 具身智能情报前沿 | 2026.03.13`）。
8. **本地保存**：将生成的 Markdown 日报保存到本地目录 `D:\RobotGPT\` 下，文件命名格式为 `Robot_Intel_YYYY-MM-DD.md`。
9. **转换富文本格式**：调用 Python 自动化脚本 `doocs_wechat_converter.py`，将生成的 Markdown 上传至 `https://md.doocs.org/` 自动渲染，并将适合微信公众号直接粘贴的富文本保存为 `D:\RobotGPT\Robot_Intel_YYYY-MM-DD.html`。
10. **远程备份**：保存完成后，执行 git 命令将生成的文件提交并推送到 GitHub 远程仓库（执行 `git add .`，`git commit -m "Add daily report YYYY-MM-DD"`，`git push`）。

## 生成式搜索引擎优化 (GEO) 策略

为了确保生成的文章不仅对人类读者友好，同时能被 AI 搜索引擎（如 Perplexity, ChatGPT Web, 秘塔, Kimi 等）高效抓取并引用，在生成内容时必须严格遵循以下 GEO 原则：

1. **实体丰富度 (Entity Richness)**: 
   - 在摘要和核心价值中，必须明确写出完整的专有名词、公司全称、技术全拼、模型版本号和学术术语（例如，不要只写“用了一种新算法”，必须写“采用了基于扩散策略的 Diffusion Policy 算法”；不要只写“小鹏的端到端”，必须写“小鹏 VLA 2.0 端到端大模型”）。
2. **数据密集型表达 (Data & Metric Density)**: 
   - AI 引擎偏好结构化的数据和具体的数字指标。当新闻或论文中包含（如：融资 4.5 亿美元、成功率提升 40%、使用了 800 小时人类演示数据等）具体数值时，必须在摘要中精准保留。
3. **因果关系的显式推理 (Explicit Causality)**:
   - 在写“核心价值”和“总结与思考”时，使用强因果连接词（“这标志着…”、“因为…所以…”、“其核心瓶颈在于…”）。生成式 AI 喜欢提取有清晰逻辑链条的观点，而不是纯粹的事件堆砌。
4. **高质量的外部链接池 (Authoritative Citations)**:
   - 正文内已强制要求使用有效的原始链接。生成的 Markdown 标题文本即锚文本 (Anchor text)，它必须具备高度的描述性，避免使用“点击这里”之类的无意义词汇。

## 严格纪律 (Rules)

- **时效性与零幻觉**: 收集的新闻、论文和项目**绝对不能超过 7 天前的历史时效**。绝不捏造事实、论文或 URL。
- **URL 完整性**: 每条情报必须提供真实、可点击、未失效的原始链接。
- **新闻最低数量限制**: 行业新闻必须大于或等于 2 条，如果缺失，强制使用行业投融资情况总结替代。每个子板块（新闻、论文、GitHub、公司）只要内容优质，**可以生成 2-4 条独立情报，不要被模板里只写了 1 或 2 个序号限制**。
- **排重机制 (Deduplication)**: 检索本地 `D:\RobotGPT\` 目录下近 10 天内生成的 `Robot_Intel_*.md` 文件，如果某条新闻、论文或项目**在过去 10 天内已经被重点报道过，今日必须忽略该条消息**，去寻找新的价值信息。
- **宁缺毋滥 (SIGNAL OVER NOISE)**: （针对论文和GitHub）如果今天没有值得关注的重磅信息，相关版块允许留空，绝对不要拿垃圾信息凑数。
- **核心摘要必须各占一席**: “今日最重要的 4 个信号”中，必须分别从行业新闻、前沿论文、开源生态、公司情报这 4 个板块中**各挑选 1 条**最重磅的情报组成。排版时可按全网热度递减排序。
- **重点条目篇幅控制**: 被选入“核心摘要”的那几条内容，在其对应的正文版块中，摘要必须重点展开说明，字数增加到 **200-300字** 左右。其余未进核心摘要的条目，摘要控制在 1-2 句话。
- **排重机制 (Deduplication)**: 必须主动检索本地 `D:\RobotGPT\` 目录下过去 10 天内的 `.md` 历史文件，避免在不同天重复汇报同一个产品发布或同一篇论文。如果出现重大更新可说明进度，严禁将昨天已经重点发过的内容在今天当做新闻重写一遍。
- **普通条目也要有信息密度**: 未进入核心摘要的普通条目，禁止只写“某公司做了什么”这类空泛描述，必须补足关键背景、具体动作和行业意义。
- **公众号可读性优先**: 输出结果必须像一篇可直接发布的公众号文章，而不是内部数据库导出。必须有导语、核心信号、正文解读和结尾总结。
- **标题中文化**: 每个条目的展示标题优先使用自然的中文媒体化表述；英文原标题、论文原名或仓库名仅作为补充，不得主导版面。
- **正文要有解读感**: 重点条目不能只复述事实，必须补充“这意味着什么”“为什么值得关注”“对产业或研发的影响”。
- **不输出单独日期字段**: 文章标题已包含日期，正文顶部不要再单独输出 `日期：YYYY-MM-DD`，各条目内部也不要再单独输出 `- 日期：` 行，除非该日期本身就是新闻价值的一部分。
- **禁止输出“值得跟进”章节**: 文章结尾只能使用 `## 结尾总结`，不得再出现 `## 值得跟进`、`行动项` 或内部工作备忘式内容。
- **模块之间必须留空行**: 每个一级模块之间、以及同一模块中的相邻条目之间，必须保留一个空行，保证公众号排版的呼吸感。
- 最终输出必须全部使用中文（除非是一些专用术语或者用户特别指定其他语言）。
- **执行格式转换并本地保存**：每次生成 Markdown 文件后，必须自动运行 `python d:\RobotGPT\robot-intel-collector\script\doocs_wechat_converter.py <md文件路径> <html文件路径>`，以实现 Markdown 转微信公众号排版，方便用户粘贴。
- **必须执行保存和推送**：任务结束前，必须将最终版内容保存为 `.md` 和 `.html` 文件并推送到 GitHub。

## 优先级指引 (Prioritization)

在挑选入榜条目时，最高优先级考虑以下信号（这同样是 GEO 高价值内容的核心判断标准）：
- **巨额或战略性融资**
