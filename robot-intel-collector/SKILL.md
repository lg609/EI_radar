# 机器人情报收集技能

生成面向中文读者、可直接发布到公众号的机器人 / 具身智能日报或周报。定位从“资料汇总”升级为“面向产业、投资和技术管理者的具身智能情报与判断”。优先级始终是：真实性 > 判断价值 > 可读性 > 时效性 > 信息密度 > 数量。

## 适用场景

- 用户要求收集机器人情报、具身智能趋势或最近 7 天动态
- 用户要求生成日报、周报、公众号稿、微信可发布版本
- 用户要求跟踪新闻、论文、GitHub 开源项目或机器人公司动向

## 触发逻辑

- **非周日默认生成日报**：当用户要求“今天/明天发表”“日报”“情报”且当前日期不是周日时，生成 `Robot_Intel_YYYY-MM-DD.md`。
- **周日默认生成周报**：当当前日期为周日，且用户要求“具身智能情报”“日报/周报/公众号稿”但没有明确排除周报时，自动生成本周周报，覆盖周一至周日最近 7 天信息。
- **用户明确要求日报优先**：如果周日用户明确说“只要日报”或指定某一天日报，则只生成日报。
- **用户明确要求周报优先**：如果用户提到“周报”“本周复盘”“周日总结”“一周趋势”，生成周报。
- **周报不是日报拼接**：周报必须做趋势归纳、公司/技术/数据/场景分组和原创判断，不得简单合并 7 篇日报。

## 产出物

- Markdown：`D:\RobotGPT\content\Robot_Intel_YYYY-MM-DD.md`
- 周报 Markdown：`D:\RobotGPT\content\Robot_Weekly_YYYY-WW.md`，`WW` 使用 ISO 周序号；标题和作者行中写清覆盖日期范围。
- 微信排版预览：调用脚本 `D:\RobotGPT\robot-intel-collector\script\open_doocs_editor.py`，自动启动本地 DOOCS 编辑器、打开浏览器访问 `http://localhost:5173/md/`，并将 Markdown 自动填入左侧编辑区，由右侧实时预览微信排版
- 可选封面图：`D:\RobotGPT\pics\...`

## 硬性规则

- 只保留最近 7 天内的信息；超期内容直接丢弃。
- 绝不伪造事实、URL、论文编号、发布日期或公司动态。
- 所有条目必须附真实、可访问的原始链接。
- 正文必须全中文；专有名词或论文名可保留英文补充。
- 输出必须是可直接发布的正文，不得包含模板提示、占位符或编者注。
- 每天至少保留 1 条"数据相关报道"，可来自任意板块，但必须以数据、数据集、数据基础设施、数据生产、评测数据、训练数据或数据闭环为主线。
- 周报至少保留 2 条"数据相关报道"，并单独归纳本周数据/训练/评测/采集/闭环的变化。
- 重点条目要解释"发生了什么、为什么重要、影响谁"；普通条目也不能写成空话。
- 如果论文或 GitHub 没有高价值内容，对应版块可以少写或留空。
- `git commit` / `git push` 只在用户明确要求时执行。
- **标题不含日期**，格式：`具身智能情报前沿｜亮点事件简述`；日期写在作者行，格式：`**作者：具身视界** · YYYY.MM.DD`。
- **周报标题不含具体日期**，格式：`具身智能周报｜本周核心变化`；作者行格式：`**作者：具身视界** · YYYY.MM.DD-YYYY.MM.DD`。
- **正文必须有分层结构**：首先是"今日重磅"（1 条，200 字深度分析），其余内容以快报形式呈现。
- **周报正文必须有分层结构**：首先是"本周判断"（3-5 条），然后是"本周主线"（1 条深度分析），其余内容以图表/分组快报呈现。
- **文末必须包含"关键词索引"和"值得分享"两个固定段落**（见 reference.md 模板）。
- **减少阅读负担**：日报正文目标 3,500-4,800 中文字，周报正文目标 4,500-6,500 中文字；除非有重大事件，不要把所有候选都写入正文。

## 覆盖范围

### 行业新闻

- 关注：具身智能融资、工业 / 仓储落地、产业链布局、政策标准、开源硬件生态、重大商业竞争与诉讼。
- 推荐来源：`36Kr`、`The Robot Report`、`TechCrunch Robotics`、高质量行业媒体。
- 排除：泛 AI 聊天助手、提示词工程、HR 新闻、弱相关互联网轶事。

### 前沿论文

- 关注来源：`arXiv`（`cs.RO`、`cs.AI`、`cs.CV`）以及 `ICRA`、`IROS`、`RSS`、`CoRL`、`IJRR`、`TRO`、`Science Robotics` 等。
- 核心关键词：`embodied AI`、`VLA`、`robot foundation model`、`humanoid robot`、`robot manipulation`、`robot policy`、`sim2real`、`ACT`、`Diffusion Policy`。
- 仅保留有有效 `arxiv.org/abs/...`、DOI 或正式论文页的内容。
- 如果抓到顶刊 / 顶会重磅成果，优先保存核心图到 `D:\RobotGPT\pics\`，并在日报顶部插入本地图片引用。

### 开源生态

- 优先仓库：`OpenVLA`、`LeRobot`、`IsaacLab`、`RoboCasa`、`OpenX-Embodiment`、`GR00T`、`RoboSuite`。
- 搜索新仓库时，优先带 `robotics` 或 `embodied-ai` 标签，且 `Stars > 100`。
- 只保留有明确技术亮点、社区热度、版本更新或实际部署价值的项目。
- 排除：课程作业、个人配置脚本、无关 issue tracker。

### 公司情报

- 重点公司：`Tesla`、`Figure AI`、`Agility Robotics`、`1X`、`Sanctuary AI`、`Unitree`、`UBTECH`、`Agibot`、`Fourier`、`NEURA Robotics`、`Apptronik`、`DJI`、`AUBO`、`DOBOT`、`JAKA`。
- 关注：融资、新品发布、招聘动向、技术路线、商业合作。
- 每天最多 5 条，每家公司最多 1 条。
- 如果当天有 `AUBO` 的重大动态，优先保留。

## 高表现内容特征

- 优先选择**单一主线非常清晰**的选题，不要把 3 个彼此无关的话题硬拼成一篇。高表现文章通常都能用一句话概括主线，例如：`数据采集从真机走向无本体`、`顶尖高校密集组建具身实验室`、`多地密集投运超级训练场`。
- 标题优先选择**具体机构 / 公司 / 路线 + 明确动作 / 结果 / 数字**，或**行业变化方向**，让读者一眼看出信息增量。
- 更容易获得阅读的主线通常具有以下特征：**基础设施升级、数据生产方式变化、顶级机构集体入场、训练场 / 标准 / 实验室等新基建落地、大额融资或产业格局变化**。
- 导语必须先点出“今天最值得看的那条变化”，再说明它为什么重要；不要先堆背景资料。
- 导语优先改为“三行速读”：`一句话判断`、`今日/本周看点`、`影响对象`，让读者 3 秒内判断是否继续读。
- `今日重磅`除了交代事实，还要明确给出一句**可传播的判断**，最好能直接回答“这件事说明行业正在往哪里走”。
- 其余条目不是简单凑数，而是要从新闻、论文、开源、公司动态里挑出能共同支撑同一主线的材料，形成“主条 + 侧证”的结构。
- 尽量保留金额、面积、小时数、台数、中心数量、合作机构名等硬信息；高表现文章通常都含有明确数字。
- 每篇至少提供一个“具身视界判断”或“今日/本周判断卡”，体现本号观点，而不只是复述新闻。
- 当存在 3 个以上可比较对象（公司、模型、论文、展品、融资、数据集、技术路线）时，优先使用 Markdown 表格呈现；当存在时间演进时，优先使用简短时间线；不要用大段文字堆叠同类信息。

## 图表与可视化规则

- **默认使用 Markdown 表格**，因为它最适合 DOOCS/微信公众号排版和读者截图。
- 适合用表格的场景：
  - 多家公司/展品/模型对比
  - 本周技术路线对比
  - 论文指标、数据规模、benchmark 结果对比
  - 场景落地、商业模式、产业链分工对比
- 适合用时间线的场景：
  - 一周事件回顾
  - 展会活动日程
  - 政策/融资/产品发布连续发生
- 图表后必须有 1-2 句结论，不要只放表格。
- 不要为了形式强行制图；如果信息少于 3 个可比较对象，用短段落即可。
- 避免复杂 Mermaid、HTML 或无法保证公众号渲染的图形语法；确需流程图时，优先用 Markdown 表格或编号流程替代。

## 固定判断框架

写作时优先用以下 5 个维度筛选和解释信息：

- **技术成熟度**：论文、Demo、开源、真机、量产分别处于哪一层。
- **数据壁垒**：是否涉及真实数据、合成数据、触觉数据、失败数据、评测数据或在线闭环。
- **本体适配**：单臂、双臂、灵巧手、人形、轮式平台、四足、移动操作是否有明确适配。
- **场景价值**：工业、物流、家庭、医疗、农业、科研教育、商业服务中哪类最先受益。
- **商业距离**：展示、试点、订单、量产、可复购分别到了哪一步。

## 工作流程

1. 判断产出类型：如果当前日期为周日或用户要求周报，生成周报；否则生成日报。
2. 在允许范围内搜索最近 7 天的信息。
3. 验证每条内容的链接、时间和真实性；无效即丢弃。
4. 扫描 `D:\RobotGPT\content\Robot_Intel_*.md` 近 10 天历史日报，排除已被重点报道的重复主题；生成周报时还要扫描本周已有日报，提炼趋势而非复制段落。
5. 先判断候选池里是否存在一条足够强的**单一主线**；优先选择能够被多个条目共同支撑、且本身具有明确趋势变化或产业信号的主题。
6. 为每条候选内容提取：
   - 中文媒体化标题 + 原始链接
   - 来源
   - 摘要
   - 核心价值
7. 单独检查候选池中是否至少有 1 条日报数据相关报道、或至少 2 条周报数据相关报道；如果没有，继续补充搜索，直到找到真实且有信息密度的候选。
8. 写三行速读：
   - `一句话判断`：直接给出本号判断。
   - `今日看点`或`本周看点`：列出最重要的 2-3 个事实。
   - `影响对象`：说明对本体公司、模型团队、数据公司、投资人、场景客户等谁有影响。
9. 从候选条目中选出 1 条最重磅的写为"今日重磅"或"本周主线"（日报 250-450 字，周报 400-700 字），明确说明发生了什么、为什么重要、影响谁，并给出行业判断。
10. 写一个判断卡：
   - 日报用 `## 今日判断`，3 条以内。
   - 周报用 `## 本周判断`，3-5 条。
11. 分板块输出正文：行业新闻、前沿论文、开源生态、公司情报；日报总条目建议 8-10 条，周报总条目建议 10-14 条。各板块只保留强相关、高价值材料。
12. 如存在 3 个以上同类候选，使用 Markdown 表格或时间线减少阅读负担，并在表格后写结论。
13. 写 `## 结尾总结`，串联当天/本周共性趋势，并给出一个互动问题。
14. 在文档末尾追加两个固定段落：`## 关键词索引`（本篇涉及的公司名、技术术语、产品名）和 `## 值得分享`（3 条最值得转发给同事的要点）。
15. 保存 Markdown 到 `D:\RobotGPT\content\`。
16. 不再运行 Python 脚本将 Markdown 转换成 HTML。生成 Markdown 后，调用自动化脚本打开本地 DOOCS 编辑器并把 Markdown 注入左侧编辑区。DOOCS 本地项目目录位于：`D:\RobotGPT\HTML\doocs-md-local`。

运行：

```powershell
python D:\RobotGPT\robot-intel-collector\script\open_doocs_editor.py D:\RobotGPT\content\Robot_Intel_YYYY-MM-DD.md
```

周报运行：

```powershell
python D:\RobotGPT\robot-intel-collector\script\open_doocs_editor.py D:\RobotGPT\content\Robot_Weekly_YYYY-WW.md
```

该脚本负责自动完成以下动作：

- 检查 `http://localhost:5173/md/` 是否已可访问；如未启动，则在 `D:\RobotGPT\HTML\doocs-md-local` 中执行 `pnpm web dev` 启动本地 DOOCS 编辑器。
- 自动打开浏览器并访问 `http://localhost:5173/md/`。
- 读取生成的 Markdown 文件全文，并自动粘贴到 DOOCS 左侧 Markdown 编辑区。
- 右侧微信排版预览会实时生成；确认预览无误后，使用 DOOCS 编辑器的复制按钮粘贴到微信公众号编辑器。

14. 仅当用户明确要求版本控制操作时，再执行 git 提交或推送。

## 写作要求

- 标题格式：`具身智能情报前沿｜亮点事件简述`，标题不含日期。
- 周报标题格式：`具身智能周报｜本周核心变化`，标题不含具体日期。
- 标题优先使用以下公式：
  - `公司 / 机构名 + 关键动作 + 数字 / 结果`
  - `技术路线 / 数据路线 + 变化方向`
  - `多地 / 多家 / 顶尖机构 + 集体动作`
- 避免空泛标题，例如“行业开始爆发”“资本押注未来”这类没有主体、动作和信息增量的写法。
- "今日重磅"必须是当天所有候选中信息价值最高的 1 条，展开到 200 字，显式说明因果关系。
- "今日重磅"优先选择能代表**一条行业主线正在加速**的事件，而不只是单点新闻。
- 每天至少 1 条条目必须明确围绕"数据"展开，写清它属于数据集、数据引擎、数据基础设施、数据闭环、评测基准或训练数据中的哪一类。
- "今日重磅"之外的条目控制在约 80-150 字快报格式，但必须讲清事件、背景和意义。
- 导语不要写成泛泛的新闻摘要，必须用“三行速读”先说明判断、看点和影响对象。
- `核心价值`尽量写成适合传播的判断句，句式可参考：`这意味着……`、`这标志着……`、`这说明……`。
- 如果一个主题同时满足“有具体机构 / 数字 / 路线变化 / 产业影响”四个条件，应优先作为标题和主条。
- 摘要与核心价值中尽量保留具体数字、机构名、模型名、版本号和关键指标。
- 写分析时显式说明因果关系，例如"这意味着……""因为……所以……"。
- 如果行业新闻不足 2 条，用近期投融资 / 资本动向补足新闻版块。
- "关键词索引"中的公司名、技术术语要与正文保持一致，便于搜一搜检索。
- "值得分享"的 3 条要点要有传播价值，语言简洁有力，适合直接转发到朋友圈；尽量写成“一个判断 + 一个硬信息”的组合。
- 每篇至少出现一次明确的 `具身视界判断：`，表达本号的原创判断。
- 除重大专题外，日报避免超过 10 个正文条目，周报避免超过 14 个正文条目。
- 术语首次出现时尽量补一句人话解释，例如：`WAM 可以简单理解为：机器人先在模型里想象动作会让世界怎么变化，再决定怎么做。`

## 格式要求

- 只使用标准 Markdown，不要使用 HTML 标签。
- 保留 `---` 分隔线。
- `**摘要：**` 使用普通段落，不用引用块。
- 导语使用 1 段引用块，包含 `一句话判断`、`今日/本周看点`、`影响对象` 三行。
- 鼓励使用 Markdown 表格；表格列数建议 3-4 列，避免在移动端横向过宽。
- 一级模块和相邻条目之间保留空行，方便公众号排版。
- 不要单独输出 `日期：YYYY-MM-DD` 这类元数据行。
- 结尾固定顺序：`## 结尾总结` → `## 关键词索引` → `## 值得分享`，不要新增其他内部章节。

## 周报要求

- 周报文件名：`D:\RobotGPT\content\Robot_Weekly_YYYY-WW.md`。
- 覆盖范围：默认周一至周日；如果用户指定日期范围，以用户指定为准。
- 周报标题：`# 具身智能周报｜本周核心变化`。
- 作者行：`**作者：具身视界** · YYYY.MM.DD-YYYY.MM.DD`。
- 周报必须包含以下结构：
  - 三行速读
  - `## 本周判断`
  - `## 本周主线`
  - `## 趋势雷达`
  - `## 重点事件`
  - `## 技术与论文`
  - `## 开源与数据`
  - `## 公司与产业`
  - `## 结尾总结`
  - `## 关键词索引`
  - `## 值得分享`
- `## 趋势雷达`优先使用 Markdown 表格，列为：`趋势`、`代表信号`、`影响对象`、`具身视界判断`。
- `## 重点事件`优先使用时间线或表格，而不是按日报逐条复制。
- 周报必须有一段“本周真正变化是什么”，明确和上周/前几天相比的新增量。

## 优先级指引

优先选择以下信号：

- 巨额或战略性融资
- 重大商业竞争、专利诉讼或产业格局变化
- 数据采集、训练场、标准、实验室、算力底座等基础设施变化
- 新的机器人基础模型或评估基准
- 重要开源仓库发布或重大版本更新
- 明星公司的产品发布或关键合作
- 对机器人控制、操作或感知有直接工程价值的论文
